#### ⚠️ 設計書との差異（改善推奨）

##### 1. レスポンシブデザインのフィルター表示方法

**設計書の要件:**
- デスクトップ（1024px以上）: サイドバーにフィルターを表示
- タブレット（768px - 1023px）: フィルターをドロップダウンで表示
- スマートフォン（767px以下）: フィルターをモーダルで表示

**現状の実装:**
- すべての画面サイズでフィルターをドロップダウンで表示（検索バーの横に配置）

**影響:**
- デスクトップでの使いやすさがやや低下（サイドバーにフィルターがある方が見やすい）
- スマートフォンでの使いやすさがやや低下（モーダルの方が画面スペースを有効活用できる）

**優先度:** 中（基本的な機能は動作しているが、UX向上のため改善推奨）

**推奨対応:**
- デスクトップ: サイドバーにフィルターを表示（または、現在の実装を維持）
- スマートフォン: フィルターボタンをクリックするとモーダルでフィルターを表示

##### 2. アクセシビリティ

**設計書の要件:**
- Tabキーで各要素にフォーカス移動
- EnterキーでTODOアイテムを選択
- Escキーでフィルターを閉じる
- 各要素に適切なaria-labelを設定
- 検索バーにaria-describedbyを設定

**現状の実装:**
- Tabキーでのフォーカス移動: 実装済み（shadcn/uiのコンポーネントが対応）
- EnterキーでTODOアイテムを選択: 未実装（現在はクリックのみ）
- Escキーでフィルターを閉じる: 未実装（Selectコンポーネントが対応している可能性あり）
- aria-label: 一部未実装
- aria-describedby: 未実装

**影響:**
- キーボード操作の一部が使用できない
- スクリーンリーダーでの使いやすさがやや低下

**優先度:** 中（基本的な機能は動作しているが、アクセシビリティ向上のため改善推奨）

**推奨対応:**
- EnterキーでTODOアイテムを選択できるようにする（CardにonKeyDownイベントを追加）
- 検索バーにaria-describedbyを追加
- 各フィルター要素にaria-labelを追加

##### 3. エラーメッセージの表示

**設計書の要件:**
- 検索キーワードが255文字を超えた場合: "検索キーワードは255文字以内で入力してください"

**現状の実装:**
- maxLength={255}で入力制限しているため、エラーメッセージは表示されない

**影響:**
- エラーメッセージは表示されないが、入力制限により問題は発生しない

**優先度:** 低（maxLengthで制限しているため、実用上問題なし）

**推奨対応:**
- 現状の実装で問題なし（maxLengthで制限しているため）
