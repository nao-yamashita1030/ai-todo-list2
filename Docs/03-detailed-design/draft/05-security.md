# セキュリティ詳細設計

## 7.1 認証詳細設計

### 認証方式
- **認証プロバイダー**: Clerk
- **認証方式**: OAuth 2.0、Email/Password認証
- **セッション管理**: Clerkが自動的に管理（JWTベース）

### 認証フロー
1. ユーザーがログイン画面で認証情報を入力
2. Clerkが認証を処理
3. 認証成功後、JWTトークンが発行される
4. トークンはCookieに保存（HttpOnly、Secure、SameSite）
5. 以降のリクエストでトークンを使用して認証状態を確認

### セッション管理
- **セッション有効期限**: Clerkのデフォルト設定に従う
- **セッション更新**: 自動更新
- **ログアウト**: Clerkのログアウト機能を使用

### パスワードポリシー
- Clerkが自動的に管理
- 強力なパスワードポリシーを適用

## 7.2 認可詳細設計

### 認可方式
- **ロールベースアクセス制御（RBAC）**: プロジェクト単位でロールを管理
- **リソースベースアクセス制御**: リソースの所有者を確認

### ロール定義
- **owner**: プロジェクトの所有者、すべての操作が可能
- **member**: プロジェクトのメンバー、TODOの作成・編集・コメントが可能

### 権限マトリクス

| 操作 | owner | member | 非メンバー |
|------|-------|--------|----------|
| プロジェクト閲覧 | ○ | ○ | × |
| プロジェクト編集 | ○ | × | × |
| プロジェクト削除 | ○ | × | × |
| メンバー追加 | ○ | × | × |
| TODO作成 | ○ | ○ | × |
| TODO編集 | ○ | ○ | × |
| TODO削除 | ○ | × | × |
| コメント追加 | ○ | ○ | × |

## 7.3 データ暗号化

### 暗号化対象
- **通信**: HTTPS通信（TLS 1.3）
- **データベース**: Supabaseの暗号化機能を活用
- **機密情報**: 環境変数、APIキー

### 暗号化方式
- **通信**: TLS 1.3
- **データベース**: Supabaseの自動暗号化
- **環境変数**: Vercelの環境変数機能で管理

### 鍵管理
- **APIキー**: Vercelの環境変数で管理
- **データベース接続情報**: Vercelの環境変数で管理
- **Clerk認証情報**: Vercelの環境変数で管理

## 7.4 セキュリティ対策詳細

### 対策1: SQLインジェクション対策
- **対策内容**: Prisma ORMを使用してパラメータ化クエリを自動生成
- **対象**: すべてのデータベースクエリ
- **実装方法**: Prisma Clientを使用

### 対策2: XSS対策
- **対策内容**: Reactの自動エスケープ機能を活用
- **対象**: すべてのユーザー入力
- **実装方法**: Reactのデフォルト動作、必要に応じてDOMPurifyを使用

### 対策3: CSRF対策
- **対策内容**: SameSite Cookie属性を設定
- **対象**: すべてのCookie
- **実装方法**: Clerkの設定で自動的に適用

### 対策4: 入力値バリデーション
- **対策内容**: Zodスキーマでサーバーサイドバリデーション
- **対象**: すべてのユーザー入力
- **実装方法**: Server ActionsでZodスキーマを使用

### 対策5: レート制限
- **対策内容**: Vercelのレート制限機能を活用
- **対象**: APIエンドポイント
- **実装方法**: Vercelの設定で自動的に適用

### 対策6: Row Level Security (RLS)
- **対策内容**: SupabaseのRLS機能でデータベースレベルでのアクセス制御
- **対象**: すべてのテーブル
- **実装方法**: SupabaseのRLSポリシーを設定
