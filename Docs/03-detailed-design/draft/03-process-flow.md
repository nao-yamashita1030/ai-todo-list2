# 処理フロー

## 5.1 主要処理フロー

### TODO作成処理
```
[ユーザー] → [TodoForm] → [Server Action: createTodo] → [Validation] → [TodoService] → [Database]
                                                                    ↓
                                                              [エラー時] → [エラーメッセージ表示]
```

### TODO更新処理
```
[ユーザー] → [TodoForm] → [Server Action: updateTodo] → [Auth: 権限チェック] → [Validation] → [TodoService] → [Database]
                                                                        ↓
                                                                  [権限なし] → [403エラー]
```

### TODO削除処理
```
[ユーザー] → [TodoItem] → [Server Action: deleteTodo] → [Auth: 権限チェック] → [TodoService] → [Database]
                                                                        ↓
                                                                  [権限なし] → [403エラー]
```

### TODO一覧取得処理
```
[ユーザー] → [TodoListPage (Server Component)] → [TodoService] → [Database] → [表示]
```

### プロジェクト作成処理
```
[ユーザー] → [ProjectForm] → [Server Action: createProject] → [Validation] → [ProjectService] → [Database]
                                                                        ↓
                                                                  [project_membersにowner追加]
```

### コメント追加処理
```
[ユーザー] → [CommentForm] → [Server Action: createComment] → [Validation] → [CommentService] → [Database]
```

## 5.2 処理詳細

### TODO作成処理の詳細
- **開始条件**: ユーザーがログイン済み、プロジェクトへのアクセス権限あり
- **処理ステップ**:
  1. フォームデータを取得
  2. Zodスキーマでバリデーション
  3. 現在のユーザーIDを取得（Clerk）
  4. プロジェクトへのアクセス権限を確認
  5. データベースにTODOを保存
  6. 変更履歴を記録
  7. 成功レスポンスを返却
- **終了条件**: TODOが正常に作成された
- **エラー時の処理**: エラーメッセージを表示し、フォームを再表示

### TODO更新処理の詳細
- **開始条件**: ユーザーがログイン済み、TODOへの編集権限あり
- **処理ステップ**:
  1. フォームデータを取得
  2. Zodスキーマでバリデーション
  3. 現在のユーザーIDを取得（Clerk）
  4. TODOの所有者またはプロジェクトメンバーか確認
  5. データベースでTODOを更新
  6. 変更履歴を記録
  7. 成功レスポンスを返却
- **終了条件**: TODOが正常に更新された
- **エラー時の処理**: エラーメッセージを表示し、フォームを再表示

### TODO削除処理の詳細
- **開始条件**: ユーザーがログイン済み、TODOへの削除権限あり
- **処理ステップ**:
  1. TODO IDを取得
  2. 現在のユーザーIDを取得（Clerk）
  3. TODOの所有者またはプロジェクトオーナーか確認
  4. データベースでTODOを削除（CASCADEで関連データも削除）
  5. 変更履歴を記録
  6. 成功レスポンスを返却
- **終了条件**: TODOが正常に削除された
- **エラー時の処理**: エラーメッセージを表示

### TODO一覧取得処理の詳細
- **開始条件**: ユーザーがログイン済み
- **処理ステップ**:
  1. 現在のユーザーIDを取得（Clerk）
  2. プロジェクトID（オプション）を取得
  3. ユーザーがアクセス可能なプロジェクトのTODOを取得
  4. フィルタ条件を適用（ステータス、優先度など）
  5. ソート処理
  6. 結果を返却
- **終了条件**: TODO一覧が正常に取得された
- **エラー時の処理**: エラーページを表示

## 5.3 例外処理フロー

### 認証エラー
- **発生条件**: ユーザーがログインしていない、またはセッションが無効
- **処理内容**: ログイン画面にリダイレクト
- **エラーメッセージ**: "ログインが必要です"

### 権限エラー
- **発生条件**: ユーザーがリソースへのアクセス権限がない
- **処理内容**: 403エラーを返却
- **エラーメッセージ**: "この操作を実行する権限がありません"

### バリデーションエラー
- **発生条件**: 入力データがバリデーションルールに違反
- **処理内容**: エラーメッセージを表示し、フォームを再表示
- **エラーメッセージ**: 各フィールドのバリデーションエラーメッセージ

### データベースエラー
- **発生条件**: データベース操作が失敗
- **処理内容**: エラーログを記録し、ユーザーにエラーメッセージを表示
- **エラーメッセージ**: "処理中にエラーが発生しました。しばらくしてから再度お試しください"

### リソース不存在エラー
- **発生条件**: 指定されたIDのリソースが存在しない
- **処理内容**: 404エラーを返却
- **エラーメッセージ**: "指定されたリソースが見つかりません"

## 5.4 バリデーションフロー

### TODOデータのバリデーション
- **対象項目**: 
  - `title`: 必須、1文字以上255文字以下
  - `description`: オプション、10000文字以下
  - `status`: 'todo', 'in_progress', 'done' のいずれか
  - `priority`: 'high', 'medium', 'low' のいずれか
  - `due_date`: オプション、日付形式
  - `project_id`: 必須、UUID形式
- **チェック内容**: Zodスキーマでバリデーション
- **エラーメッセージ**: 各フィールドのバリデーションエラーメッセージ

### プロジェクトデータのバリデーション
- **対象項目**: 
  - `name`: 必須、1文字以上255文字以下
  - `description`: オプション、10000文字以下
- **チェック内容**: Zodスキーマでバリデーション
- **エラーメッセージ**: 各フィールドのバリデーションエラーメッセージ

### コメントデータのバリデーション
- **対象項目**: 
  - `content`: 必須、1文字以上10000文字以下
  - `todo_id`: 必須、UUID形式
- **チェック内容**: Zodスキーマでバリデーション
- **エラーメッセージ**: 各フィールドのバリデーションエラーメッセージ
