# ビジネスロジック設計

## 6.1 ビジネスルール

### ルール1: プロジェクト所有権
- **ルール名**: プロジェクト所有権
- **内容**: プロジェクトの作成者が自動的にオーナーとなり、project_membersテーブルにownerロールで登録される
- **適用範囲**: プロジェクト作成時

### ルール2: TODOアクセス権限
- **ルール名**: TODOアクセス権限
- **内容**: ユーザーは以下の場合にTODOにアクセス可能:
  - TODOの作成者
  - TODOが属するプロジェクトのメンバー
- **適用範囲**: TODOの取得、更新、削除時

### ルール3: TODO編集権限
- **ルール名**: TODO編集権限
- **内容**: ユーザーは以下の場合にTODOを編集可能:
  - TODOの作成者
  - TODOが属するプロジェクトのメンバー（ownerまたはmember）
- **適用範囲**: TODOの更新時

### ルール4: TODO削除権限
- **ルール名**: TODO削除権限
- **内容**: ユーザーは以下の場合にTODOを削除可能:
  - TODOの作成者
  - TODOが属するプロジェクトのオーナー
- **適用範囲**: TODOの削除時

### ルール5: プロジェクトメンバー追加
- **ルール名**: プロジェクトメンバー追加
- **内容**: プロジェクトのオーナーのみがメンバーを追加可能
- **適用範囲**: プロジェクトメンバー追加時

### ルール6: 変更履歴の記録
- **ルール名**: 変更履歴の記録
- **内容**: TODOの作成、更新、削除、ステータス変更時に自動的に変更履歴を記録
- **適用範囲**: TODOの変更時

### ルール7: カテゴリ・タグのスコープ
- **ルール名**: カテゴリ・タグのスコープ
- **内容**: カテゴリとタグはプロジェクト単位で管理され、プロジェクト固有またはグローバルに設定可能
- **適用範囲**: カテゴリ・タグの作成・使用時

## 6.2 ビジネスロジック詳細

### ロジック1: TODO作成
- **目的**: 新しいTODOを作成する
- **入力**: TODOデータ（title, description, status, priority, due_date, project_id, category_id, tags）
- **処理**: 
  1. バリデーション
  2. 現在のユーザーIDを取得
  3. プロジェクトへのアクセス権限を確認
  4. TODOを作成
  5. タグを関連付け（todo_tagsテーブル）
  6. 変更履歴を記録（action: 'created'）
- **出力**: 作成されたTODOデータ
- **例外処理**: バリデーションエラー、権限エラー、データベースエラー

### ロジック2: TODO更新
- **目的**: 既存のTODOを更新する
- **入力**: TODO ID、更新データ
- **処理**: 
  1. バリデーション
  2. 現在のユーザーIDを取得
  3. TODOの編集権限を確認
  4. 変更前の値を取得（履歴用）
  5. TODOを更新
  6. タグの関連付けを更新
  7. 変更履歴を記録（action: 'updated', old_value, new_value）
- **出力**: 更新されたTODOデータ
- **例外処理**: バリデーションエラー、権限エラー、リソース不存在エラー、データベースエラー

### ロジック3: TODO削除
- **目的**: TODOを削除する
- **入力**: TODO ID
- **処理**: 
  1. 現在のユーザーIDを取得
  2. TODOの削除権限を確認
  3. 変更前の値を取得（履歴用）
  4. TODOを削除（CASCADEで関連データも削除）
  5. 変更履歴を記録（action: 'deleted'）
- **出力**: 削除成功のレスポンス
- **例外処理**: 権限エラー、リソース不存在エラー、データベースエラー

### ロジック4: TODOステータス切り替え
- **目的**: TODOのステータスを切り替える
- **入力**: TODO ID、新しいステータス
- **処理**: 
  1. 現在のユーザーIDを取得
  2. TODOの編集権限を確認
  3. 現在のステータスを取得
  4. ステータスを更新
  5. 変更履歴を記録（action: 'status_changed', old_value, new_value）
- **出力**: 更新されたTODOデータ
- **例外処理**: 権限エラー、リソース不存在エラー、データベースエラー

### ロジック5: プロジェクト作成
- **目的**: 新しいプロジェクトを作成する
- **入力**: プロジェクトデータ（name, description）
- **処理**: 
  1. バリデーション
  2. 現在のユーザーIDを取得
  3. プロジェクトを作成
  4. 作成者をproject_membersにownerロールで追加
- **出力**: 作成されたプロジェクトデータ
- **例外処理**: バリデーションエラー、データベースエラー

### ロジック6: プロジェクトメンバー追加
- **目的**: プロジェクトにメンバーを追加する
- **入力**: プロジェクトID、ユーザーID、ロール
- **処理**: 
  1. 現在のユーザーIDを取得
  2. プロジェクトのオーナーか確認
  3. 追加するユーザーが存在するか確認
  4. 既にメンバーでないか確認
  5. project_membersに追加
- **出力**: 追加されたメンバー情報
- **例外処理**: 権限エラー、リソース不存在エラー、データベースエラー

## 6.3 計算ロジック

### 計算1: リマインダー判定
- **計算式**: `due_date - current_date <= reminder_days`
- **入力**: 期限日（due_date）、リマインダー日数（reminder_days、デフォルト: 3日）
- **出力**: リマインダーが必要かどうか（boolean）
- **精度**: 日単位

### 計算2: TODO進捗率
- **計算式**: `(完了TODO数 / 全TODO数) * 100`
- **入力**: プロジェクトIDまたはユーザーID
- **出力**: 進捗率（0-100のパーセンテージ）
- **精度**: 整数パーセンテージ
